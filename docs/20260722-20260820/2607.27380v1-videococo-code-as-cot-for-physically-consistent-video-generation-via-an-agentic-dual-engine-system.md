## 摘要
文本生成视频模型已获得显著的视觉质量，但仍难以生成物理一致的动态，因为场景的时间演变必须从高度压缩的文本提示中隐式推断。现有的思维链方法引入中间计划或视觉状态，但这些表示通常不可执行或时间上稀疏，限制了它们实例化和控制完整时空过程的能力。为解决这一局限，我们提出VideoCoCo，一种智能双引擎框架，其中可执行的Blender代码作为过程级思维链。给定文本提示，编码智能体合成一个Blender程序，明确指定场景及其时间演变。可执行的模拟引擎运行该程序生成确定性的时空草稿，随后通过生成式视频引擎基于草稿条件编辑将其转化为逼真视频。这种分解将过程级推理与高保真视觉实现分离。为使视频编辑器适应模拟草稿，我们构建了VideoCoCo-3K，一个精选的草稿-指令-目标三元组数据集。VideoCoCo将OmniWeaving基线在PhyGenBench上从0.475提升至0.558，在VBench-2.0上从52.18提升至77.88，在两个基准上均达到最佳平均分。这些结果表明，可执行代码为物理一致的视频生成提供了一种有效、可控且可检查的中间表示。

## Abstract
Text-to-video models have achieved remarkable visual quality, yet they still struggle to generate physically consistent dynamics because the temporal evolution of a scene must be inferred implicitly from a highly compressed text prompt. Existing chain-of-thought approaches introduce intermediate plans or visual states, but these representations are typically non-executable or temporally sparse, limiting their ability to instantiate and control the complete spatiotemporal process. To address this limitation, we introduce VideoCoCo, an agentic dual-engine framework in which executable Blender code serves as a process-level chain of thought. Given a text prompt, a coding agent synthesizes a Blender program that explicitly specifies the scene and its temporal evolution. The executable simulation engine runs the program to produce a deterministic spatiotemporal draft, which is subsequently transformed into a photorealistic video by a generative video engine through draft-conditioned editing. This decomposition separates process-level reasoning from high-fidelity visual realization. To adapt the video editor to simulated drafts, we construct VideoCoCo-3K, a curated dataset of draft-instruction-target triplets. VideoCoCo improves the OmniWeaving baseline from 0.475 to 0.558 on PhyGenBench and from 52.18 to 77.88 on VBench-2.0, achieving the best average score on both benchmarks. These results demonstrate that executable code provides an effective, controllable, and inspectable intermediate representation for physically consistent video generation.

### 二、论文提出的方法论

#### 核心思想

- 将“过程推理”与“视觉实现”解耦：
  - **编码智能体**将文本提示转化为可执行 Blender 程序；
  - **模拟引擎**在沙盒中运行程序，渲染出确定性的、低逼真但时间稠密的**时空草稿**；
  - **生成引擎**（视频编辑器）基于草稿和编辑指令，将草稿重绘为高逼真视频。

#### 关键技术细节

1. **Code-as-CoT 程序合成**
   - 输入提示 \(p\)，编码智能体 \(A_{code}\) 生成自包含 Blender 程序 \(c = A_{code}(p)\)。
   - 代码需显式声明物体、物理属性、运动及时间演化，具有三重优势：
     - **显式**：不留模糊空间；
     - **可执行**：程序可实际运行并产出一致结果；
     - **可检查**：代码可读、可编辑、可重复执行。

2. **沙盒执行与草稿渲染**
   - 在隔离的 Blender 环境 \(B\) 中运行程序，得到草稿 \(d = B(c)\)。
   - 草稿刻意保持低逼真（白色黏土风格），但每帧都对应一个物理实例化的状态，形成完整的时空结构。

3. **编辑指令构造**
   - 指令智能体 \(A_{edit}\) 读取原始提示和草稿，生成外观导向的编辑指令 \(e = A_{edit}(p, d)\)。
   - 指令描述主体、材质、光照和风格，并明确避免重新定义草稿中已有的运动，确保与草稿互补。

4. **草稿条件视频编辑**
   - 编辑模型 \(G_\theta\) 同时接收草稿 \(d\) 和指令 \(e\)，输出最终视频 \(\hat{v} = G_\theta(d, e)\)。
   - 草稿锚定时空过程，指令规定外观，从而将问题转化为“重风格化”而非“从零生成”。

5. **VideoCoCo-3K 数据集**
   - 为了训练编辑器适应白色黏土草稿，构建了 3000 个“草稿-指令-目标”三元组。
   - 使用教师编辑器 Seedance 2.0 生成对应逼真目标：\(y_i = G_T(d_i, e_i)\)。
   - 数据中排除了评估基准的提示及其近似重复，保留原始提示和程序作为元数据，便于审计和扩展。

6. **训练目标**
   - 在 VideoCoCo-3K 上对编辑器进行条件去噪训练：
     \[
     L(\theta) = \mathbb{E}_{(d,e,y), t, \epsilon} \left[ \| \epsilon - \epsilon_\theta(z_t, t, d, e) \|_2^2 \right]
     \]
   - 初始化自 OmniWeaving，可全量微调或采用 LoRA 参数高效微调。

7. **端到端推理**
   - 用户仅输入文本提示，系统自动完成：代码生成 → 沙盒渲染草稿 → 编辑指令 → 最终视频。全程无需人工介入，且所有中间产物可检查、可复现。

### 六、论文的主要结论与发现

- **PhyGenBench**：VideoCoCo 将 OmniWeaving 平均分从 0.475 提升至 0.558，为表中最佳；力学、光学、材料三个类别排名第一，热学排名第二（仅次于 Wan2.2-TI2V-5B）。提升最大的集中在材料和热学，说明基于代码的草稿在视觉先验较弱的维度贡献最大。

- **消融结论**：
  - Tune-Free 已可以提升平均分（0.475→0.506），证明草稿本身提供了物理动态，而非仅仅来自额外训练。

### 七、优点

- **创新性**：首次将可执行代码作为视频生成的过程级 CoT，解决了已有中间表示不可执行/时间稀疏的问题。
- **解耦设计**：将物理过程推理（模拟引擎）与视觉外观实现（生成引擎）分离，每个引擎可专注自身优势。
- **透明可解释**：代码、草稿和指令均为可读、可编辑、可重跑的人工产物，便于诊断和迭代。
- **自动化与扩展性**：端到端运行无需人工标注；构建的 VideoCoCo-3K 数据集可用于后续研究和跨模型适配。
- **实验验证**：双基准上均取得领先结果，特别是在视觉先验较弱的物理维度上提升显著，证明了方法的普适性和可解释性。

### 八、不足与局限

- **额外推理开销**：模拟渲染 → 草稿编辑增加了流水线延迟，且较直接 T2V 生成更多步骤。
- **模拟器表达能力受限**：依赖 Blender 模拟器，对湍流液体、复杂材料破坏等高度复杂现象，难以零样本合成，通用性有限。
- **数据集规模受限**：仅 3K 三元组，可能不足以覆盖所有物理场景；教师模型 Seedance 2.0 的选择会引入特定分布偏差。
- **泛化性存疑**：只在 OmniWeaving 上作为基座验证，未测试能否同样提升其他视频生成模型；代码智能体错误或指令智能体失败时缺乏鲁棒性分析。
- **评估偏差**：PhyGenBench 依赖 GPT-4o 作为裁判，结果可能受大模型主观性影响；VBench-2.0 所采用的物理维度也未必能完全反映真实物理合理性。
- **潜在运动保持问题**：编辑器虽经过草稿条件训练，但在复杂场景或草稿运动不清晰时，仍可能无法完全忠实保留草稿中的动力学，存在幻觉风险。
