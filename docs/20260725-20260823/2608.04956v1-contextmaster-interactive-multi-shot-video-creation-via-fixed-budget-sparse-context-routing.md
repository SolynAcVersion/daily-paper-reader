## 摘要
近期的视频模型越来越多地在单一模型中支持生成、参考条件和编辑，但通常将它们作为固定输入上的独立操作。实际创作跨越多个镜头展开，需要一个模型能够从文本生成、跟随参考或编辑源素材，同时维护共享历史。我们将这种设置形式化为交互式多镜头视频创作（IMVC），并引入ContextMaster，一个具有角色感知上下文表示的统一模型，用于这些操作。交互式模型必须保持对不断扩展的历史的访问，而不允许每次去噪步骤的上下文读取成本增长。ContextMaster将可重用的干净上下文状态与固定预算的稀疏上下文路由相结合，并使用ConstraintSink保持任务约束可见。为了解决稀疏上下文访问和少量去噪步骤推理的双重挑战，我们提出了一种两阶段特权上下文蒸馏框架，该框架通过一致性蒸馏将密集教师的全上下文行为转移，然后通过分布匹配细化部署展开。在三个原始任务上的实验表明，与专门的基线相比，任务完成度和跨镜头一致性有所提高。用户研究进一步验证了灵活组合的工作流程，而该模型在单个GPU上达到16 FPS。

## Abstract
Recent video models increasingly support generation, reference conditioning, and editing within a single model, yet typically expose them as separate operations over fixed inputs. Practical creation unfolds across multiple shots, requiring one model to generate from text, follow a reference, or edit source footage while maintaining shared history. We formalize this setting as interactive multi-shot video creation (IMVC) and introduce ContextMaster, a unified model with a role-aware context representation for these operations. An interactive model must retain access to an expanding history without allowing the context read cost at each denoising step to grow. ContextMaster combines reusable clean context states with fixed budget sparse context routing and uses ConstraintSink to keep task constraints visible. To address the dual challenges of sparse context access and inference with few denoising steps, we propose a two-stage privileged context distillation framework, which transfers full context behavior from a dense teacher through consistency distillation and then refines deployment rollouts with distribution matching. Experiments on the three primitive tasks demonstrate improved task fulfillment and consistency across shots over specialized baselines. User studies further validate flexibly composed workflows, while the model reaches 16 FPS on a single GPU.

## 2. 论文提出的方法论

### 2.1 核心思想

ContextMaster 的核心主张是：**将干净（clean）的上下文状态与任务约束分离，并以固定预算的稀疏路由方式注入生成过程**，从而兼顾历史引用与计算效率。

### 2.2 关键组件

- **角色感知上下文表示（Role-Aware Context Representation）**：为每个上下文片段赋予角色标签（如"主角"、"场景"、"约束"），使模型理解不同历史片段在生成中的功能差异。
- **可复用干净上下文状态（Reusable Clean Context States）**：对不同去噪时间步可复用的上下文特征进行预先计算与缓存，避免每步重复编码。
- **固定预算稀疏上下文路由（Fixed-Budget Sparse Context Routing）**：不将全部历史拼接到当前输入，而是以固定预算从历史中**选择性地路由**最相关的上下文 token，保证不同历史长度下计算开销守恒。
- **ConstraintSink**：一种特殊的记忆槽位（memory sink），确保任务约束（如文本 prompt、参考图像）在所有去噪步骤中始终可见，不被稀疏路由丢弃。

### 2.3 训练框架：两阶段特权上下文蒸馏

由于存在双重挑战——**稀疏上下文访问**（可能丢失信息）和**少量去噪步数推理**（效率与质量的权衡），论文提出两阶段蒸馏：

1. **阶段一：一致性蒸馏（Consistency Distillation）**——以密集教师模型（可访问全部上下文的特权模型）的全上下文行为为监督信号，将行为迁移到稀疏上下文的学生模型上，学习一致性映射。
2. **阶段二：分布匹配细化（Distribution Matching Refinement）**——针对学生模型实际部署时的 rollout 分布，通过分布匹配（而非仅模仿教师输出）进一步微调，弥补训练与推理之间的分布偏移。

### 2.4 算法流程（文字描述）

1. 输入多镜头历史片段与当前任务约束（文本/参考图/编辑目标）。
2. 提取各片段的干净上下文状态并对历史进行角色标注。
3. 通过固定预算稀疏路由选择相关历史 token，并以 ConstraintSink 保障约束可见。
4. 将稀疏上下文与当前输入特征拼接，送入去噪网络进行少步去噪生成。
5. 训练时先由密集教师蒸馏一致性，再用分布匹配优化部署展开。
